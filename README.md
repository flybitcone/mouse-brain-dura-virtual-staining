# Paired brightfield and fluorescence images of mouse brain and dura mater — code

Source code for image preprocessing, animal-level partitioning, virtual fluorescence
staining benchmarks and evaluation. Code release: v1.0.0; license: MIT.

## Data

Dataset DOI: https://doi.org/10.5281/zenodo.23493761

This DOI was reserved when the code package was prepared; dataset upload/publication
is still in progress. The link will resolve publicly after Zenodo publication.
Data are licensed CC BY 4.0. Download all ten ZIP volumes and follow the dataset README
to reconstruct/extract the archive. Images, arrays and model weights are not in this repository.

Copy the extracted `raw_data/` and `preprocessing_reports/` directories to this repository
root, and the extracted `deep learning/dataset_patches/` directory under `deep learning/`.
The resulting layout is:

```text
preprocess.py
raw_data/
preprocessing_reports/
deep learning/
  dataset_patches/<task>/<train|val|test>/{input,target,metadata.csv}
  train.py
  benchmark.py
  eval.py
  models/
  utils/
reference_metadata/
benchmark_reference/
```

## Installation

Create an isolated Python environment. For the recorded PyTorch 2.5.1/CUDA 12.4
training environment, use Python 3.11 (a compatibility-oriented installation recipe,
not a frozen record of every historical run):

```sh
conda create -n virtual-staining python=3.11 -y
conda activate virtual-staining
python -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cu124
python -m pip install -r requirements.txt
```

Use the official PyTorch installation instructions for other GPUs, platforms or CPU-only
execution. Dependency versions in `requirements.txt` are not a complete lock file;
test compatibility in your environment. Historical per-run versions are retained in
`benchmark_reference/**/environment.json`. They differ between execution batches.
`requirements-preprocess.txt` records the separate preprocessing versions; these are
not intended to be installed into the Python 3.11/PyTorch 2.5.1 training environment.

## Run the five-model benchmark

From this repository root, with the released patch arrays in place:

```sh
python "deep learning/audit_dataset.py" --root "deep learning/dataset_patches" --output dataset_audit.json
python "deep learning/benchmark.py" --models unet resunet attunet pix2pix cyclegan --tasks BFtoDAPI BFtoIBA1 BFtoCD206 BFtoLYVE1 BFtoNeutrophil --seeds 42 43 44 --epochs 300 --batch-size 2 --device cuda
```

The explicit `--models` list restricts execution to the manuscript's five baselines.
Results and checkpoints are written under `deep learning/benchmark_runs/`.
Inspect `benchmark_reference/**/config.json` for the original task-specific settings;
the command above is a runnable common configuration, not a guarantee of identical
historical results. Archived absolute paths identify the original runs and should be
replaced using command-line `--data-root` and `--output-root` options.

Train one model:

```sh
python "deep learning/train.py" --model unet --task BFtoDAPI --data-root "deep learning/dataset_patches" --device cuda
```

Evaluate a checkpoint generated by training (replace `PATH_TO_CHECKPOINT`):

```sh
python "deep learning/eval.py" --model unet --checkpoint PATH_TO_CHECKPOINT --task BFtoDAPI --data-root "deep learning/dataset_patches" --subset test --device cuda
```

Use `--help` on each entry point for additional options. Complete training was not
repeated when this GitHub bundle was assembled. Exported benchmark metrics/configurations
are included; trained weights and patch-level prediction files remain outside this code bundle.

## Preprocessing from raw TIFFs

The released patches can be used directly. For a new build, use a separate checkout
with raw TIFFs, the preprocessing dependencies and sufficient disk space:

```sh
python preprocess.py --inspect
python -m unittest test_preprocess -v
python preprocess.py --build
python preprocess.py --validate
```

The build writes to `preprocessing_build/`. The script refuses an existing staging
directory. On Windows, `Publish-PreprocessedData.ps1` promotes a validated build and
replaces existing processed-data directories; inspect the script and use a dedicated
working copy before promotion. `finalize_preprocessing.py`,
`validate_preprocessing_leakage.py` and `verify_preprocessing_batch.py` provide
additional checks. The released benchmark partition is in `reference_metadata/split.json`.

## Contents and citation

`benchmark_reference/` contains historical configurations, environment records and
aggregate metrics, including additional exploratory runs. `benchmark_reference_table.csv`
contains the manuscript's balanced five-model summary.
`SHA256SUMS.txt` covers the distributed source bundle (excluding itself).

Please cite both the dataset DOI above and the accompanying article when published.
The article DOI and the GitHub release URL must be added after they become available.
